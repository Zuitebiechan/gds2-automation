# GDS2 云端部署架构设计

## 概述

本文档描述 GDS2 云端部署的两阶段架构：
1. **Phase 1**: 使用 SM2 USB + USB over IP (概念验证)
2. **Phase 2**: 使用 MDI 2 + VCI Proxy (生产架构)

---

### 数据流

```
1. 用户操作 Web UI
       │
       ▼
2. Flask 后端调用 RPA 自动化
       │
       ▼
3. GDS2 通过 J2534 API 请求数据
       │
       ▼
4. Scanmatik 驱动处理请求
       │
       ▼
5. VirtualHere Client 转发 USB 数据
       │ (TCP over 互联网)
       ▼
6. VirtualHere Server 接收
       │
       ▼
7. SM2 USB 物理设备
       │ (OBD-II 协议)
       ▼
8. 车辆 ECU 响应
```

### 优点
- 快速验证概念
- 不需要修改 GDS2 或驱动
- 使用现有硬件 (SM2 USB)

### 缺点
- USB over IP 延迟较高 (~50-100ms 额外延迟)
- 稳定性依赖网络质量
- 无法添加精确时间戳

### 数据流 (带时间戳)

```
1. 云端 GDS2 发送 J2534 请求
       │
       ▼
2. 虚拟 J2534 驱动转发到 VCI Proxy
       │ (TCP, 端口 9000)
       ▼
3. VCI Proxy 接收请求
       │
       ├──► 记录请求时间戳 (T1)
       │
       ▼
4. VCI Proxy 转发给 MDI 2
       │ (本地以太网, <1ms)
       ▼
5. MDI 2 发送到车辆
       │
       ▼
6. 车辆响应返回 MDI 2
       │
       ▼
7. VCI Proxy 接收响应
       │
       ├──► 记录响应时间戳 (T2)
       │
       ├──► 上传 {数据, T1, T2} 到云端数据库
       │
       ▼
8. VCI Proxy 转发响应到云端 GDS2
       │
       ▼
9. GDS2 显示数据 (可能有网络延迟, 但时间戳准确)
```

### 时间戳协议

```python
@dataclass
class TimestampedMessage:
    sequence: int           # 消息序列号
    request_time_us: int    # 请求发送时间 (微秒)
    response_time_us: int   # 响应接收时间 (微秒)
    direction: str          # 'to_vehicle' 或 'from_vehicle'
    channel_id: int         # J2534 通道 ID
    protocol: int           # 协议类型 (CAN, ISO15765, etc.)
    data: bytes             # 原始数据
```

### 优点
- 精确时间戳，解决网络抖动问题
- MDI 2 以太网直连，低延迟
- 可扩展到多车辆

### 缺点
- 需要购买 MDI 2 (~$500-1000)
- 需要开发虚拟 J2534 驱动和 VCI Proxy
- 架构更复杂

## 从 Phase 1 到 Phase 2 的过渡

### 代码复用

| 组件 | Phase 1 | Phase 2 | 复用程度 |
|------|---------|---------|---------|
| Web UI | Flask + templates | 相同 | 100% |
| Java Agent | 相同 | 相同 | 100% |
| RPA 自动化 | 相同 | 相同 | 100% |
| J2534 驱动 | Scanmatik (现成) | 虚拟驱动 (开发) | 0% |
| 现场软件 | VirtualHere (现成) | VCI Proxy (开发) | 0% |
| 时间戳系统 | 无 | 新增 | - |

### 迁移步骤

```
Phase 1 完成后:
│
├── 验证云端 GDS2 基本功能
│
├── 收集性能基准 (延迟、稳定性)
│
└── 开始 Phase 2 开发
       │
       ├── 1. 开发 VCI Proxy (Python)
       │      - J2534 API 封装
       │      - TCP 服务器
       │      - 时间戳模块
       │
       ├── 2. 开发虚拟 J2534 驱动 (C/C++)
       │      - 实现 J2534 API
       │      - TCP 客户端连接
       │      - 注册到 Windows
       │
       ├── 3. 获取 MDI 2 硬件
       │      - 测试以太网连接
       │      - 验证与 VCI Proxy 兼容性
       │
       └── 4. 集成测试
              - 完整数据流测试
              - 时间戳准确性验证
              - 长时间稳定性测试
```

## 安全考虑

### Phase 1
- VirtualHere 使用 SSL 加密
- 限制源 IP 访问
- VPN 连接 (可选)

### Phase 2
- VCI Proxy 与云端使用 TLS 加密
- 双向证书认证
- 消息签名防篡改

```python
# VCI Proxy 安全配置示例
class SecureVCIProxy:
    def __init__(self):
        self.ssl_context = ssl.create_default_context(ssl.Purpose.SERVER_AUTH)
        self.ssl_context.load_cert_chain('client.crt', 'client.key')
        self.ssl_context.load_verify_locations('ca.crt')
```
